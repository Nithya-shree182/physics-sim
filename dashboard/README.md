# Dashboard: Physics Attestation Layer

Plotly Dash, one page, NTT DATA branded. Started with the rest of the system by `./pal.sh` (http://127.0.0.1:8050), or alone on its stand-in plant with
`.venv-pal/bin/python dashboard/app.py`. Design record: [../DECISIONS.md](../DECISIONS.md) D9 (the redesign) and D13 (the alarm rule); screenshots in `../docs/screens/`.

## Sources (the switch on the toolbar)

| Source | What it is |
|---|---|
| **Isaac Sim (live)** | The live simulator (`workspace/pal_live.py`, 250 Hz physics): rows arrive over HTTP and runs are sent back. Run, stop, repeat, box mass, speed bar, test fault. |
| **Stand-in plant** | A Pinocchio plant (link masses +-3%, friction x1.15, sensor noise) under a joint-impedance controller. Not Isaac Sim; the toolbar says so. |

## The page

- **Arm & residual tab.** The Isaac picture is large; the schematic twin (Pinocchio) is a small inset at its bottom right. Beside them: payload estimate, largest residual, run summary and alerts.
  Under the picture: pick style, Run / Stop, repeat, the box mass (0 to 8 kg, the top of the validated ladder) and speed (0 to 100% of the bar, where 100% is half of each joint's velocity limit); "More controls" for per-joint speeds and a
  test fault. Below: the residual, torque or payload chart for the selected joint, per-joint bars and the torque breakdown.
- **Analysis tab.** Per-box facts (set mass, estimated, error) and a plain-language account of the last cycle, written offline by fixed rules (`views.narrate`); no language model is called.
- **Benchmark tab.** The three movement styles on a real pick (`docs/o6pick_summary.json`, regenerated by `tools/summarize_o6pick.py`), a plain-language explanation of each (`views.explain_styles`, every number read from the file),
  this session's scores and the residual floor against speed.
- **Panels** (Telemetry, Payload, About) and the alert list (the bell). No pop-ups.

## What is real

- **The analysis code** is the project's own: `observers/residual.py` (20 Hz zero-phase filter), the payload formula of `observers/payload.py` on a sliding 1.2 s window, `observers/pose_mask.py`.
- **A live row** is `[t, q, qd, tau_measured, q_des, tau_applied, held, run_id]`, each group DOF wide. `IsaacSource.next_block` slices it by the arm's joint count; it was hard-coded for seven joints until 2026-11-09, which
  made every live channel wrong on the UR10e.
- **Payload.** The running estimate uses the measured (net) torque. Before the grasp the tool is empty, and what the estimator reads then is its zero (about 0.3 to 0.4 kg, the simulator's 5% mass mismatch); it is subtracted as a tare. The
  per-box figure is the median over the settled middle of each carry (the first 2.5 s and the last second are skipped: the running mean needs time to converge, and braking to put the box down pulls it low).
- **Faults** (`engine.Analyzer`): a pick is compared with a healthy run of the same task (style, box mass, speed), recorded automatically the first time; choosing a fault with no reference first runs a healthy pick. Three channels: the torque residual
  per joint, the tracking error per joint, and the command lag (the slope of the tracking error on the joint velocity), each compared with the reference at the same time into the pick and scored against a 3 s-or-so calibration spread
  with a floor (1% of each joint's torque limit for torque, 20 ms for lag). A joint is named after |z| > 6 for 150 ms and at least 0.10 N*m and 0.5% of its limit. Settings and scores: [../docs/DETECTION_RESULTS.md](../docs/DETECTION_RESULTS.md).
  Picks without a reference are not judged for faults.
- **Speed** is capped at 50% of a joint's velocity limit everywhere (the engine clamps it; live runs refuse more).

## Known limits

Tuned on one cycle (S-curve, 60% speed, friction x8). Faults on joint 5 are not seen (the cycle barely moves it). A wrist friction fault is also labelled "stuck joint". See [../docs/TODO.md](../docs/TODO.md) items 2 to 4.

## Files

`app.py` layout and callbacks, `views.py` figures and panels (pure functions), `engine.py` sources, analysis and alerts, `assets/style.css` the look, `assets/ntt_data_logo.png` the header logo. Tests: `../tests/test_dashboard_engine.py`.
Screenshots: `PAL_DASH_TAB=an` (or `bench`) and `PAL_DASH_DRAWER=alerts` start the page on that tab or panel; headless Chrome can then capture it.

State is global in the server process (one engine), so open one browser tab. Refresh the tab after a restart. The live source and `./pal.sh` share the container name `pal-pal-live` and port 8765: run one at a time.
